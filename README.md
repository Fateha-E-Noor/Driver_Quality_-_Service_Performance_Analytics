# Driver Quality & Service Performance Analytics

## Project Overview

Ride-hailing platforms depend heavily on the quality and reliability of their driver network. Even when customer demand is high, driver cancellations, customer cancellations, incomplete rides, long vehicle arrival times, and inconsistent ratings can reduce successful ride completion and negatively affect the customer experience.

This project analyzes ride-booking and service-performance data to identify where performance deteriorates and which operational segments have higher cancellation, completion, or service-quality issues. The analysis is intended to help an operations team investigate and improve service performance.

## Business Questions

The project investigates:

- What is the overall booking completion and non-completion rate?
- Which pickup locations have the highest service-performance issues?
- What are the main reasons for driver cancellations?
- Is vehicle arrival time associated with customer cancellations?
- Are there meaningful differences between vehicle types?
- Are there time-of-day or hourly operating patterns?
- What does service quality look like from driver and customer ratings?
- Which locations should operations prioritize for further investigation?

## Data Source

The original dataset was obtained from Kaggle:

https://www.kaggle.com/datasets/anilrohan/uber-data-india?resource=download

The raw Kaggle CSV is intentionally not included in this repository. Please download it from the source link and place it in the project folder as `ncr_ride_bookings.csv` before running the notebook.

## EDA and Feature Engineering

The notebook performs exploratory data analysis on the original ride-booking data, including:

- Dataset shape, column inspection, descriptive statistics, missing-value checks, and duplicate checks.
- Booking-status, vehicle-type, location, cancellation-reason, and payment-method analysis.
- Date and time conversion for temporal analysis.
- Creation of month, day-of-week, hour, time-period, and weekend fields.
- Creation of completion, driver-cancellation, customer-cancellation, and incomplete-ride indicators.
- Creation of driver-rating, VTAT, CTAT, and ride-distance bands.
- Export of the cleaned and feature-engineered dataframe for downstream use.

The derived CSV is generated by the notebook and is not committed to this repository. This keeps the repository lightweight and avoids redistributing the dataset. The generated file is also ignored by Git.

## PostgreSQL and SQL Analysis

The feature-engineered dataframe is loaded into PostgreSQL/pgAdmin 4 in the `driver_quality` database, using the table `uber_data_cleaned`.

The notebook then runs SQL analysis for booking health, pickup-location performance, driver-cancellation reasons, VTAT bands, vehicle types, time periods, hourly patterns, ratings, and operational focus areas.

The PostgreSQL password is not stored in the notebook. Set `PGPASSWORD` in the environment or enter the password when the database-loading cell prompts for it. Optional connection variables are `PGUSER`, `PGPORT`, and `PGDATABASE`.

## SQL Analysis

`questions.sql` contains the PostgreSQL queries used to answer the eight business questions. The queries expect the feature-engineered table `uber_data_cleaned` in the `driver_quality` database.

## Power BI Dashboard and Final Report

The final deliverables are:

- A Power BI dashboard connected to the PostgreSQL table `uber_data_cleaned`.
- A PDF report containing the methodology, key findings, answers to the eight business questions, dashboard screenshots, recommendations, and limitations.

The local `report.md` file is the editable source for the final PDF and is intentionally not tracked in GitHub. After editing it, export it to:

`Driver_Quality_Service_Performance_Analytics_Report.pdf`

Recommended conversion options:

- In VS Code, open `report.md`, use Markdown preview, and choose **Print** followed by **Save as PDF**.
- With Pandoc installed, run:

```bash
pandoc report.md -o Driver_Quality_Service_Performance_Analytics_Report.pdf
```

Upload the finished PDF to the repository. Keep `report.md` local as the editable source.

## Project File

## Environment Setup

Install Python and the notebook dependencies in the selected VS Code/Jupyter environment:

```bash
python -m pip install pandas ipykernel sqlalchemy psycopg2-binary
```

For an externally managed MSYS2 Python installation, install the equivalent packages with MSYS2's package manager instead of pip.

Start PostgreSQL, create the `driver_quality` database, download the Kaggle CSV, and run the notebook cells in order.

## Reproducibility

1. Clone this repository.
2. Download the original Kaggle dataset from the link above.
3. Save it as `ncr_ride_bookings.csv` in the project folder.
4. Start PostgreSQL and create the `driver_quality` database.
5. Select the configured Jupyter kernel in VS Code.
6. Run the notebook from top to bottom.
7. Run `questions.sql` in PostgreSQL/pgAdmin 4.
8. Connect Power BI to `uber_data_cleaned` and create the dashboard.
9. Export the local `report.md` to PDF and upload the PDF as the final report.
